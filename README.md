# 《解剖一次推理：从 API 调用到 Transformer 的每一个矩阵》

> 当你 `curl` 一次大模型 API，从按下回车到屏幕上蹦出第一个字，
> 中间发生了大约 10¹⁴ 次浮点运算、几百 GB 的数据搬运和一场精密的显存调度。
> 这本书把这一次调用完整解剖开——不跳过任何一个矩阵，也不跳过任何一层工程外壳。

---

## 这本书写给谁

**主要读者**：有 1~3 年经验的软件工程师。用 30 秒自测三题：

1. 你能手算一个 2×3 矩阵乘 3×2 矩阵吗？
2. 你调用过至少一次 LLM API（哪怕只是玩）吗？
3. 看到「KV Cache」「PagedAttention」这些词，你是不是"眼熟但说不清"？

三题都答"是"，这本书就是为你写的。你不需要机器学习背景——本书用到的数学不超过矩阵乘法、点积和指数函数，超出的地方（如方差、旋转矩阵）会在使用处现场补齐。

**次要读者**：正在转向 AI Infra 的后端工程师，需要在两周内建立对推理链路的完整认知。

**这本书不写给谁**：想学模型训练与调参的读者（本书只讲推理，训练机制仅在解释"参数为什么是这个样子"时带过）；想要框架 API 手册的读者（本书讲多年不变的原理，不讲随版本变化的接口）。

## 全书主线：解剖一次 API 调用

全书只讲一个故事。你在聊天界面里打下一句诗，客户端发出这样一次请求：

```
POST /v1/chat/completions
{
  "model": "llama-2-70b",
  "messages": [
    {"role": "system", "content": "你是一位精通古诗的助手"},
    {"role": "user",   "content": "帮我补全这首诗：白日依山尽，黄河入海"}
  ],
  "max_tokens": 32, "temperature": 0.7, "stream": true
}
```

几百毫秒后，屏幕上流出「流」，然后是「。欲穷千里目……」。本书的每一章负责解剖这次调用的一段：

```
      ┌─────────────────── 工程外壳（Part IV）───────────────────┐
      │  HTTP 接入 · Chat Template · 排队调度 · 显存分配 · 批处理 · 反分词 · 流式推送  │
      │   ┌────────────── 算法内核（Part I~III）──────────────┐   │
请求 ──┼──►│ 字符串 → token(ch1) → 向量+位置(ch2) → 80×[注意力   │   │
      │   │ (ch3~4) + FFN(ch5) + 残差/归一化(ch6)] → 分布(ch7) │──┼──► 流式吐字
      │   │ → 采样出字 → 喂回循环(ch8)                        │   │
      │   └──────────────────────────────────────────────┘   │
      │        KV Cache 安放(ch9) · GPU 喂饱术(ch10)            │
      └─────────────────────────────────────────────────────┘
                     第 0 章：先把整张图走一遍
```

所有章节共用同一个例子、同一组真实模型尺寸（LLaMA-2 70B），数字从第 0 章一路对账到附录。

## 全书符号与数值约定

以 LLaMA-2 70B 为基准模型，全书所有章节共用：

| 符号 | 含义 | 取值 |
|------|------|------|
| $n$ | 当前序列长度（token 数） | prompt 为 10，随生成推进 |
| $V$ | 词表大小 | 32000 |
| $d$（即 $d_{\text{model}}$） | 隐藏维度 | 8192 |
| $L$ | 层数 | 80 |
| $h$ | Query 头数 | 64 |
| $g$ | KV 头数（GQA 分组数） | 8 |
| $d_k$ | 每头维度（$d/h$） | 128 |
| $d_{ff}$ | FFN 中间维度 | 28672 |

矩阵形状一律标注为 (行, 列)，如 $X: (n, d)$；向量默认为行向量。

> **一处贯穿全书的教学简化**：真实的 LLaMA 分词器对汉字按 UTF-8 字节切分，一个汉字可能对应 1~3 个 token。为保证例子可读，本书假设每个汉字恰好一个 token（第 1 章会具体说明这一简化不影响任何原理）。

## 如何读这本书

- **第一遍顺序读**：章节沿数据流排列，前后有依赖。先读第 0 章拿地图，再逐站深入。
- **跳读**：每章开头有「本章回答的问题」与前置依赖声明，配合附录 A 可独立阅读任意一章。
- **动手**：核心章节有 ≤30 行的纯 NumPy 代码锚点，复制即可运行；章末练习标 ★ 的题是下一章伏笔，答案见附录 B。
